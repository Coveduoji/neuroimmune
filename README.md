# 神经免疫防御 (NeuroImmune Defense)

> 用「神经系统 + 免疫系统」的架构，把多模型编排成一个**成本不对称、会学习、可调姿态**的企业防守有机体。

**当前状态**：架构已落地为可运行的产品雏形（原型 + Web 工作台）。快速开始见下，开发进展见 [`PROGRESS.md`](PROGRESS.md)，产品定位见 [`PRODUCT.md`](PRODUCT.md)。

## 快速开始

```bash
# 1. 最小闭环原型（零 key 跑通架构，mock 模型）
cd prototype
python3 main.py                                  # 读内置样例 data/sample.jsonl

# 2. Web 工作台（FastAPI + React）
cd ../backend && pip install -r requirements.txt
uvicorn app:app --port 8000                      # 后端 + 24h syslog 值守
cd ../frontend && npm install && npm run dev     # 打开 http://localhost:5173
```

真实模型：复制 `prototype/.env.example` 为 `prototype/.env` 填入你自己的 key（详见 [`backend/README.md`](backend/README.md)）。

## 命名

原名 `mixmodle` 只描述了「混模型」这个**手段**，承载不了后续梳理出来的**内涵**。本项目的内核是：多模型只是零件，真正的价值在于把它们编排成一个「防守有机体」——它同时具备：

- **神经系统**：感知（杏仁核）、注意力（全局工作空间）、认知（系统 1/2）
- **免疫系统**：固有免疫、适应性免疫、免疫耐受

两者合起来，生物学上叫「神经免疫」(neuroimmunology)。故命名 **神经免疫**。

## 1. 背景

### 1.1 灵感起点

最初的想法叫 `mixmodle`：**把各种模型混起来用**，有没有可能。

### 1.2 发散脉络

这个想法经历了几轮递进式的发散，每一轮都推翻了上一层的边界：

| 轮次 | 切入角度 | 关键结论 |
|---|---|---|
| ① | 按「混法」分 | 路由网关、集成投票、级联、权重融合、Mixture-of-Agents。**闭源模型无法在权重层融合**，可行的混法都在编排层和输出层。 |
| ② | 按「混哪个部位」分 | 角色（红蓝对抗、脑区分工）、执行（投机解码、logit 混合）、参数（权重插值、交叉蒸馏）、上下文（共享记忆池、隐私分层）。 |
| ③ | 锁定「大脑隐喻」 | 展开为认知架构：系统 1/2、杏仁核、海马体、神经调质、抑制机制、全局工作空间。 |
| ④ | 补上「免疫系统」 | 固有/适应/免疫记忆/免疫耐受——作为**安全原生隐喻**，跟检测体系精确对应。 |
| ⑤ | 换到甲方防守视角 | 甲方四大痛点（工具烟囱、预算有限、告警疲劳、向上交代）→ 大脑四大机制映射。 |
| ⑥ | 收敛 | 六层架构 + 落地顺序 + 巅峰场景。 |

### 1.3 核心洞察（三条）

1. **大脑是胶水，不是模型。** 模型随便换（这正是 mixmodle 的根），价值全在编排、路由、记忆这几层胶水里。
2. **告警降噪。** 贵的模型只对少数告警深想，其余在边缘筛掉——把海量告警压到人能处理的量级。
3. **价值不在「看」，在「降噪 / 越用越准 / 风险档位」。** 这是与已经做烂的态势感知（SA）的根本区别。

## 2. 内容（架构）

### 2.1 总览：六层

| 层 | 大脑对应 | 一句话 |
|---|---|---|
| 感知层 | 杏仁核 + 抑制 | 只捞针 |
| 注意力层 | 黑板 / 全局工作空间 | 拼信号 |
| 认知层 | 系统 1 / 系统 2（快判断 / 深分析） | 告警降噪 |
| 响应层 | 风险旋钮 | 管理层的方向盘 |
| 记忆层 | 睡眠巩固 + 免疫记忆 | 越用越懂 |
| 免疫层 | 固有 / 适应 / 耐受 | 越用越强 |

### 2.2 各组件详解（按投产比从高到低）

#### ① 杏仁核 + 抑制（感知层）—— 投产比最高，先做

- **干什么**：一个（或一组）常驻的便宜模型，并行盯着各路信号流（日志、端点、身份、流量），只干一件事——「这段里有没有不该发生的」。产出不是告警，而是**带置信度的「不对劲」信号**。
- **怎么实现**：便宜模型做主力（Haiku / 本地 Qwen 7B/14B），每条信号流一个窄 prompt。更省的版本：**规则 + 嵌入异常做初筛**，只有初筛命中才让模型看一眼。抑制机制与它一体：杏仁核同时负责「这正常，别往上送」，用免疫耐受的误报反馈持续校准。
- **投产比**：极高。直接治告警疲劳，完全基于现有 SIEM/EDR 数据就能跑，不推翻任何投资。
- **坑**：漏报靠免疫层兜，误报靠耐受层压，**不能单独上，必须配着耐受回路一起做**。

#### ② 系统 1 / 系统 2 路由（认知层）—— 告警降噪

- **干什么**：板上高分的信号，先让便宜模型初判；没把握或太复杂，才唤醒贵模型深想。贵模型醒在**那一条**上，不醒在九千九百九十九条上。
- **怎么实现**：系统 1 对信号定性、分级、给处置建议，并输出置信度。路由门槛：`置信度 < 阈值` 或 `复杂度/分值 > 上限` → 唤醒系统 2。给贵模型一个全局成本预算，预算被旋钮动态调。
- **投产比**：极高。整套架构里最直接的钱：24 小时「看起来深度防守」，实际按需付费。
- **坑**：门槛**先用死规则，跑出数据后再用数据调**，别一上来上学习。

#### ③ 风险旋钮（响应层）—— 实现成本几乎为零，但价值巨大

- **干什么**：把「我要多安全」抽成一个管理层可拨的参数，映射到杏仁核告警阈值、系统 2 唤醒预算、响应激进程度。几档预设：宽松 / 正常 / 保守 / 战时。
- **怎么实现**：一个全局配置 + 几组阈值表。技术上半小时能做完。
- **投产比**：极高（成本 ≈ 0），但**价值完全依赖上面两层先跑起来**。
- **坑**：别在系统跑通前做旋钮，会变成「没人用的开关」。

#### ④ 黑板 / 全局工作空间（注意力层）—— 解决工具烟囱，但极易翻车

- **干什么**：所有感知信号汇到一块事件总线，统一 schema（时间、来源、资产、置信度、类型）。「竞争」= 显著性打分：单个信号置信度 + 与板上其他信号的关联度，**两个弱信号能拼成一条攻击链**。
- **怎么实现**：事件总线（NATS / Redis Streams / Kafka）+ 打分/关联步骤。跨域关联的价值在这里——端点异常登录能在板上关联到云权限变更、MFA 绕过、异常导出。
- **投产比**：高（单点工具永远做不到的）。**最大的坑：极易滑回「态势感知大屏」。** 必须死守：**黑板是路由决策点，不是展示屏幕**。分高的往下走，其余静默。

#### ⑤ 睡眠巩固 + 免疫记忆（记忆层）—— 累积型，越用越值

- **干什么**：夜里（cron）把当天黑板的原始信号、处置、决策整合成结构化记录。两个去向：(a) 检索记忆库（向量库，跨天跨月记住上下文）；(b) 回写检测（提炼新 TTP 进固有免疫规则，误报模式写进免疫耐受白名单）。
- **怎么实现**：夜间用贵模型做整合（夜里便宜/闲置，正好利用沉睡省下的算力）。与周报脚本同构，只是泛化到「所有事件」。
- **投产比**：中，**累积型**——短期看不出，三个月后「记得住」的差别会拉开。
- **坑**：整合质量决定这层是资产还是垃圾堆，值得夜间用贵模型认真做。

#### ⑥ 免疫层（固有 / 适应 / 耐受）—— 一半是现成的，一半要养

- **固有免疫**：规则引擎（Sigma/YARA/IDS 规则），快，只会认见过的。**现成的、已经做烂的，直接复用别自研**。
- **适应性免疫**：行为基线 + 异常检测（ML 或 embedding 距离），学没见过的。投产比中高，但要养数据，短期上不了。
- **免疫耐受**：误报反馈回路，把「正常业务」写进白名单。**杏仁核的配套件**，跟 ① 一起上。

### 2.3 巅峰场景（系统跑满时的样子）

> 巅峰不是「AI 自动打一切、人没了」——那是科幻。巅峰是：机器干机器该干的（常醒、秒级、关联、记忆），人站在人该站的位置（判断、担责、权衡业务），而系统让这个人看起来永远先知先觉。

**一家三千人的制造企业，安全团队五个人，凌晨 3:14。**

系统 95% 在沉睡，便宜模型例行扫日志，一天的算力成本不到一杯咖啡。

- **3:14:07** — 杏仁核在噪声里嗅到一丝极弱的不对劲：`svc_backup` 服务账号凌晨登录了一台三个月没碰过的资产。单独看是 SIEM 里注定被淹没的一条，但杏仁核没喊，只把它**贴上黑板**。
- **3:14:11** — 黑板开始「抢舞台」。身份模块贴出 MFA 绕过策略；云模块贴出往陌生 OSS 桶写数据；数据模块贴出批量导出晚跑 40 分钟。四个弱信号拼出一条链。
- **3:14:19** — 系统 2 被**精确唤醒**（只醒这一条，不醒九千条）。重建 kill chain：这是供应链投毒第一阶段。
- **3:15:40** — 风险旋钮停在「正常」档，系统**没擅自隔离**，而是把三条处置选项 + 各自业务影响推出来，要人的判断，不是要人的授权。
- **3:16:02** — 负责人把旋钮拨到「保守」，全有机体换挡，外科手术式三刀：隔离节点、冻结 OSS 桶、挂起制品发布。业务流水线继续跑，没人知道三分钟前出过事。

**白天**：复盘会上，负责人拿着系统自动写好的完整时间线、攻击链、决策日志走进董事会——尽职报告是「本来就存在的」。

**夜里**：睡眠巩固，把 TTP、攻击链、处置得失写进免疫记忆。

**两周后**：同一家族的新变种来犯，被固有免疫在边缘秒拦，**系统 2 连醒都没醒**。防守体系比两周前更强了，这次拦截没花一分钱深度算力。

## 3. 实现目标

### 3.1 落地顺序

```
第 0 步  模型统一入口（LiteLLM / one-api）—— mixmodle 的根，先接多家模型可切换
第 1 步  杏仁核 + 免疫耐受        —— 治告警疲劳，基于现有 SIEM 数据
第 2 步  系统 1/2 路由            —— 告警降噪
第 3 步  黑板（做路由不做大屏）    —— 跨域关联，拼信号
第 4 步  风险旋钮                 —— 前几步跑顺后才加
第 5 步  睡眠巩固 + 免疫记忆       —— 累积价值，长期
```

每一步都能独立闭环、独立验证投产比，不用一口气上全。

### 3.2 最小闭环

先做「**杏仁核 + 一块黑板**」：把现有工具（哪怕就 SIEM + EDR）的告警汇到同一块黑板上，一个便宜的常醒模型只判「这堆告警里哪几条值得叫醒深度分析」。先解决告警疲劳和工具烟囱两个最痛的问题，不推翻现有投资。

### 3.3 边界与明确不做的事

- **痛觉机制（自防护）暂缓**：实现方式不清晰、投产比不高，留作将来独立立项，不占主架构。
- **不做大屏**：黑板是路由，不是展示，避免重蹈态势感知覆辙。
- **不重蹈态势感知覆辙**：价值只在「降噪 / 越用越准 / 风险档位」三件事上，三件都做空、只剩统一黑板和可视化 = 又一个大屏。

## 4. 结论

### 4.1 核心原则（五条）

1. 贵的模型要「**睡眠**」
2. 便宜的模型要「**专门**」
3. 一个全局旋钮管「**状态**」
4. 一半力气花在「**抑制**」而不是「生成」
5. 记忆靠「**离线巩固**」而不是「现场硬记」

### 4.2 与态势感知的分水岭

态势感知已经做烂了，烂在三个缺失上。本项目要死死咬住这三件态势感知不做的事：

> **降噪**（把海量告警压到可处理量级）、**越用越准**（免疫记忆，不是死仓库）、**风险档位**（管理层拨档，不是被动大屏）。

三件里哪怕只做实一件，就不是大屏；三件都做空，就是重蹈覆辙。

### 4.3 下一步待细化

第 1 步（杏仁核 + 免疫耐受）的具体设计：数据流、prompt 结构、置信度怎么算、误报怎么回写——做到能直接照着写代码的程度。

## 5. 其他重要记录

### 5.1 免疫系统为什么是「安全原生隐喻」

免疫系统跟检测体系的对应精确到可以直接套用：

| 免疫机制 | 安全对应 |
|---|---|
| 固有免疫（硬编码模式匹配） | 特征库 IDS / 杀软规则 |
| 适应性免疫（学新病原体 + 记忆细胞） | 行为检测 / ML |
| 自身/非自身识别 | 基线异常检测 |
| 免疫记忆 | 威胁情报库 |
| 炎症反应（逐渐升级） | 告警分级响应 |
| 免疫耐受（不攻击自身） | 压误报 |

免疫系统进化了十几亿年才调平「误报（耐受）+ 漏报（适应）」这对矛盾——这正是 SOC 最痛的同一对矛盾。

### 5.2 对模型本身的意义（一个诚实的问题）

- **对模型本身**：几乎无意义。模型是无状态函数，编排只改变成本、延迟、记忆、注意力——全是给使用者的意义。
- **唯一的例外**：**训练回路**。若把系统积累的经验（对话、纠错、高价值案例）喂回去做微调，编排层就变成了模型的学习回路——这是唯一一条「编排层作用于模型本身」的路。
- **真正的「自我」住在模型之间**：连续性（记忆、身份、决策史）住在编排层，不在任何权重里。但**连续性 ≠ 意识**。
